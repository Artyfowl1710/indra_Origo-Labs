# Indra Origo product acceptance ledger

Active goal: turn the user's customized Indra foundation into a polished, installable local-first workstation with automatic multimodal routing, optional cloud inference, voice, a mobile companion, and useful verified agent workflows. Submission date: 3 November 2026; time unspecified. This ledger retains the full requested scope; no subsection alone proves completion. The original SIH-26-main folder remains read-only.

## Required evidence

- [x] Greetings: hi/thanks execute no tools; real tasks after a greeting still can use tools; verified against the actual desktop backend on 31 October (local model; other providers remain separate acceptance).
- [ ] Auto-routing: attached images reach the vision model/projector; text reaches the primary model; errors, cancellation, concurrent turns, return-to-text and GPU residency work.
- [ ] UI: modern dark/light themes inspired by the supplied reference, responsive layout, visible route/model/approval state, keyboard and screenshot review; offline fonts.
- [ ] Voice: local input/output, cancel/barge-in, explicit recording controls, device errors and tested audio paths.
- [ ] Android: current-backend pairing, private HTTPS/auth, revocation, attachment transfer and handoff; built APK and device/emulator tests.
- [ ] Runtime: approved runtime discovery, CPU/GPU modes, health recovery, owned shutdown, model-directory selection, measured cold/warm latency and automatic fallback.
- [ ] Packaging: reproducible pinned dependencies, offline installation path, shortcuts, version identity, update/uninstall/data preservation, clean installation and licenses.
- [ ] Workflows: inspectable task receipts/evidence, reviewed changes/undo, checkpoint/recovery and cross-device continuation integrated from existing components with implementation/UI/tests. No unsupported market-uniqueness claims.
- [ ] Existing features: sessions, files, attachments, RAG, documents, approvals, cancellation and diagnostics tested together; fix outstanding imported API/profile/build failures.
- [ ] Release gates: source/secret scan, dependency review, remote/local trust boundaries, approval isolation, no host-shell fallback, required regressions and explicit skips. Do not claim certified security or achieved superintelligence.
